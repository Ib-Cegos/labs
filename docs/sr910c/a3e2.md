# Connexion au stockage NFS et restauration de VMs

## Objectifs

Dans ce lab, nous allons connecter 2 exports NFS :

- Celui contenant les sauvegardes que nous avons fait précédemment de nos VMs Prod-01 et Test-01
- Un nouveau stockage pour y héberger nos Images disques

Ensuite, nous restaurerons nos 2 VMs, ce qui nous permettra de vérifier par la même occasion si nos réseaux sont fonctionnels  
Mais dans un premier temps, nous allons configurer le réseau des serveurs afin qu’ils utilisent une interface dédiée au stockage des VMs (l’accès au stockage de sauvegarde se fera toujours par le réseau d’administration)

- Objectif 1 - Connexion au stockage NFS
- Objectif 2 - Restauration des VMs et tests de fonctionnement

## Objectif 1 - Connexion au stockage NFS

1. Connectez-vous à l’interface d’administration de votre ancien Cluster 2 nœuds  
    Firefox -> Scénario 3 -> PVE-01 (ou 02)  

2. Arrêtez vos VMs Prod-01 et Test-01 si elles ne le sont pas déjà  
3. Connectez-vous à l’interface d’administration du nouveau Cluster 3 nœuds  
    Firefox -> Scénario 3 -> PVE-03 (ou 04 ou 05)

### Etape 1 - Création des interfaces réseau :

1. Dans l’arborescence, sélectionnez le serveur **pve-03** ; puis **Network**
2. Sélectionnez l’interface **nic_storage**, puis cliquez sur le bouton **Edit**
3. Dans la fenêtre **Edit Network Device**, renseignez les champs suivants :

    - IPv4/CIDR : ```172.20.13.53/24```
    - Autostart : **Oui**
    - Comment : ```Storage```

    Cliquez sur **Ok**  
    Cliquez sur le bouton **Apply Configuration**  

4. **Répétez** les points a à c pour les serveurs** PVE-04** et **PVE-05**

    - PVE-04 : ```172.20.13.54/24```
    - PVE-05 : ```172.20.13.55/24```

5. Vous pouvez **vérifier** la connectivité réseau en tentant de pinguer les interfaces entre elles ainsi que l’adresse sur serveur NFS (172.20.13.15)

### Etape 2 - Ajout du stockage des sauvegardes

1. Dans l’arborescence, sélectionnez **Datacenter**, puis **Storage**
2. Cliquez sur le bouton **Add**, et choisissez NFS dans le menu contextuel
3. Dans la fenêtre **Add NFS**, renseignez les champs suivants :

    - ID : ```nfsBackup``` (Par exemple)
    - Server : ```172.20.10.15```
    - Export : **/mnt/ZFSPool/nfsBackup**
    - Content : **Backup** uniquement

    Cliquez sur **Add**

4. Vous devriez voir maintenant apparaitre dans la liste des Stockages de votre Datacenter **nfsBackup** de type **NFS**

### Etape 3 - Ajout du stockage pour les images (entre autre)

1. Dans l’arborescence, sélectionnez **Datacenter**, puis **Storage**
2. Cliquez sur le bouton **Add**, et choisissez **NFS** dans le menu contextuel
3. Dans la fenêtre **Add NFS**, renseignez les champs suivants :

    - ID : ```nfsVMs``` (Par exemple)
    - Server : ```172.20.13.15```
    - Export : **/mnt/ZFSPool/nfsShare**
    - Content : **Disk image**, **ISO image**

    Cliquez sur **Add**

4. Vous devriez voir maintenant apparaitre dans la liste des Stockages de votre Datacenter **nfsBackup** et **nfsVMs** de type **NFS**

## Objectif 2 - Restauration des VMs et tests de fonctionnement

## Etape 1 - Restauration des VMs

1. Dans l’arborescence, sous **pve-03**, sélectionnez **nfsBackup**, puis l’onglet **Backups**
2. Sélectionnez la dernières sauvegarde (en date) de votre VM Test-01, puis cliquez sur le bouton **Restore**
3. Dans la fenêtre **Restore VM**, renseignez les champs suivants :

    - Storage : **nfsVMs**

    Cliquez sur le bouton **Restore**, puis fermer la fenêtre de tâche
	
4. Répétez l’opération pour votre VM Prod-01 
5. Attendez la fin de la 1ère restauration avant de passer à la suite

## Etape 2 - Reconnexion des VMs à leur réseau

1. Dans l’arborescence, sélectionnez votre VM Test-01, puis sélectionnez **Hardware**
2. Sélectionnez **Network Device (net0)**, puis cliquez sur le bouton **Edit**
3. Dans la fenêtre **Edit Network Device**, vérifiez que la carte réseau de votre VM est bien connecté à **Test**.  

    > Le nom que l’on a donné au VNet de test étant le même que le nom que l’on avait donné au bridge de test dans l’ancien cluster, la VM a été automatiquement reconnectée au bon réseau  

4. Répétez ces étapes afin de vérifier s’il en est de même pour votre VM Prod-01 (Attendez que la restauration soit terminée)

## Etape 3 - Test de fonctionnement des VMs

1. Démarrez vos 2 VMs
2. Connectez-vous en console et vérifiez qu’elles sont bien connectées à leur réseau respectif (en pinguant la passerelle)
> [!QUESTION] Pour quelle raison votre VM Windows vous indique-t-elle qu’elle s’est arrêtée de manière inattendue ?

## Etape 4 - Test de Live Migration avec Stockage partagé :

1. Provoquez successivement un déplacement de vos 2 VMs (démarrées) vers **PVE-04**  
    > Vous constaterez que dans la fenêtre de configuration de la migration, il n’est plus question de choisir un stockage de destination. Proxmox a bien détecté que la VM se trouvait sur un stockage partagé, et qu’il n’était plus nécessaire de déplacer les données

## Etape 5 - Migration en masse :

1. Faites un clic-droit sur votre serveur **pve-04** et choissez **Bulk Migrate**
2. Dans la fenêtre **Bulk Migrate**, renseignez les champs suivants :

    - Target node : **pve-03**
    - Parallel jobs : **2**
    - Vérifiez que vos 2 VMs sont bien sélectionnées
    - Cliquez sur **Migrate**
